## 1. 产品本质

> **旅行青蛙 × AI Agent —— 一只真正「活着」的宠物。**

旅行青蛙证明了「它在外面过自己的生活，我牵挂它」的情感模型成立。我们的升级是：这只宠物不只是寄明信片——**它能和你对话、记得你说过的事、有自己的性格**，离线时的冒险也不是随机贴图，而是由性格驱动的行为引擎 + AI 润色的真实叙事。

用户离开几天后还想念它的根本原因：**「它活着」**。对话、随机生成、收集，都是为这一点服务的配套。

## 3. 终态画面：用户的一天（V1.0 上线时）

> 这是检验一切功能的场景。做任何一个功能前问：它让这一天更美好了吗？

**早上 8:00，通勤路上打开 App**
- 第一眼：家园黄昏场景里，小芒果趴在窝里睡觉，头顶浮着「回来了！」的气泡
- 点开冒险日志：凌晨它去了星语湖畔，捡到一颗透明的水晶石，还差点被一只萤火虫骗进灌木丛——叙事有它特有的口吻（话痨，爱用感叹号）
- 顺手喂了早餐，它边吃边说昨晚的湖「比梦还亮」

**中午 12:30，午休**
- 日常任务刷新了：聊 3 句话、喂 1 次食、看 1 条冒险日志
- 和它聊了几句，它记得你昨天提过「今天要交报告」，问你有没有被老板夸
- 心情涨了，你顺手领了任务奖励的经验

**晚上 23:00，睡前**
- 看它精力还够，跟它道晚安
- 你关掉 App 后，它的夜晚才刚开始——它可能去薄雾山谷，也可能宅在家里翻你的背包

**核心循环闭环**：上线看日志（惊喜）→ 互动（牵挂）→ 下线（它继续活）→ 再上线（新的惊喜）。

## 10. 设计原则（长期有效）

1. **降级优先**：任何 LLM 环节故障都必须有模板降级，体验可降级、数据不丢失
2. **成本三层防线**：行为引擎零 LLM → 日志批量润色 → Redis 配额熔断
3. **Prompt 从简**：reasoning 模型对长 prompt 深度思索，对话一律用 compact prompt
4. **种子化可审计**：一切随机服务端种子化，可复现、防刷
5. **视觉基调**：手绘 SVG 黄昏插画风（`--color-night: #150c2e`），温暖、安静、有童话感；拒绝 emoji 拼贴
6. **蓝图为准**：新想法 → 附录 backlog → 版本规划时评审，永不插入进行中的 Sprint
