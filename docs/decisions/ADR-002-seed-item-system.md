# ADR-002: 种子与物品体系 —— 旅行内容化重构

- 日期：2026-08-17
- 状态：已定稿，W1 月宫打样实施中
- 关联：[种子与物品体系 Spec v1.0](../spec/seed-item-system-spec.md)（细节与验收表以 spec 为准，本 ADR 只记"为什么"）

## 背景

ADR-001 极简重构后，旅行的内容仍是完全随机的幻想地名/物品/事件（萤火森林、发光蘑菇），用户没有任何"认出"的瞬间——随机生成物天然没有情绪触发点。同时诊断发现：爽点结构是"诞生一次强爆+长尾疲软"，集邮维度零分（背包无 UI、无体系），轻游戏会话缺少 30 秒主动操作。

## 决策

**旅行内容从"随机生成"转为"种子衍生"**：预存用户认得的文化素材（现实景点/历史/神话/名著/世界文明）为种子库，每趟旅行锚定一个种子，围绕其背景、角色、物产衍生故事。

配套决策（全部见 spec，此处只列结论与理由）：

| 决策 | 结论 | 关键理由 |
|------|------|---------|
| 叙事呈现 | 陌生化转述：宠物视角描述，不写真实人名/地名 | 用户"认出"的瞬间 > 被告知；版权护盾（沿用 Q6 IP 转译先例）；宠物误读本身是萌点 |
| 素材边界 | 首发只做公共领域（现实地标/历史/神话/名著），现代 IP 走转译缓行 | 合规风险地图 T1/T2/T3 |
| 物品图片 | 内容入库时批量预生成，不走运行时；统一画风不随宠物 | 物品是固定目录不是无限生成；图鉴是未来社交货币，必须同物同图 |
| 物品存储 | ItemDef 在内容文件（版本化），发现状态在 DB | 定义要 diff/review/回滚；发现状态是运行时共享状态 |
| 物品属性 | 口粮/伴手礼/护身符/古董四类，属性决定命运 | 解决"只进不出无粘性"：收获→投入→消耗/交换→再收获循环 |
| 行囊 | 背包无上限 + 行囊 3 槽位 | 决策权重从"扔什么"（痛苦）移到"带什么"（期待），守纯牵挂 |
| 交换 | L1 单机=种子 NPC，永不降级，性格决定是否发起 | 架构零改动；provider 接口隔离，V1.1 换真人撮合不动调用方 |
| 首发现冠名 | 物品定义级，纯荣誉徽章无加成 | 不用损失厌恶也能制造回访驱动；有加成会变竞速焦虑 |
| 归来交互 | 首页信封，点击拆信看日记+收获 | 两段式期待感（看到信封→拆开），优于自动弹窗 |
| 收藏页 | 图鉴+历史日记一体两标签 | 少页面；图鉴管"集"，日记管"忆" |

## 红线（违反即 bug）

R1 纯牵挂零损失厌恶 / R2 交换不降级 / R3 传说不可消耗 / R4 不加速 / R5 陌生化转述。

## 社交预留（只留缝不建表）

角色引用全部带类型（`npc:*`/`pet:*`/`user:*`）；离线事件统一 feed；展示名经 `display_name()` 包一层；不建好友/互访/挂单表。

## 影响

- `gamedata.py` 的 ADVENTURE_ZONES/ADVENTURE_EVENTS 被种子内容文件取代（旧五区作为"通用野区"保留或废弃由打样验证决定）
- `pet.inventory` 结构升级（名字字符串 → item_id 引用），需一次性迁移
- 行为引擎从"均匀随机串珠子"升级为"选种子→抽基调→抽卡组"，LLM 润色注入种子背景
- 前端新增打包页、收藏页、信封交互

## 验证

按 spec §11 页面操作预期表 + §12 全局验收标准执行（pytest + E2E 探针 + 浏览器走查）。
