## 2. 核心用户流程（V1.0 终态）

```
首次: 注册 → 送蛋 → 问答引导(6题, 蛋"感应"主人) → 照料蛋(2-3天)
      → 孵化起名 → 诞生(生成专属形象) → 开始养
日常: 打开App → 〔离线>30min〕回归通知+冒险日志 → 宠物主动搭话
      → 喂食/聊天/做任务 → 下线(宠物继续生活)
```

## 3. 已实现模块的需求确认（✅ 现状 = 需求基线，可提调整）

> 这部分已经开发完成并验收，列出真实实现作为基线。如有不满意的数值/规则，现在提，改配置即可。

### 3.1 蛋与孵化 ✅
- 注册送 1 枚 normal 蛋；照料 +15 孵化值/次，日限 3 次（45/天）；满 100 可孵化 → **约 2-3 天孵出**
- 孵化时种子化生成：物种（normal 池 4 种：狐狸/垂耳兔/狸花猫/柴犬）、颜色（6 色）、五维性格（0-100）、性格标签（傲娇/话痨/胆小/吃货/高冷/戏精）、天赋 1-2 个、技能 1 个
- ❓ **D1 宠物数量**：数据模型支持多宠，但流程/UI 按一宠设计。**推荐：V1.0 一人限一宠**（旅行青蛙模型，情感聚焦；多宠随 V1.1 社交一起开放）
- ❓ **D2 稀有蛋**：rare/legendary 生成池已建成，但**目前没有任何获取途径**。推荐：V1.0 不开放（一宠制下开放稀有蛋必然引入"换宠"，伤害情感模型），随 V1.1 多宠一起开放

### 3.2 对话 ✅
- 性格 → compact system prompt（约 125 字符）→ SSE 流式输出；输入输出双向敏感词过滤，命中用性格化兜底话术
- 短期记忆：最近 N 轮上下文；**事实记忆**：异步从对话抽取主人事实（名字/喜好/重要事件）注入后续对话
- 每次对话心情 +2
- ❓ **D3 对话轮次限制**：成本模型规划"免费用户 10 轮/日"，**目前未实现**（只有 per-pet 2 万 token/日 的 BudgetGuard）。推荐：V1.0 实现 10 轮/日限制（内购预留点位，也防成本失控），前端剩余轮次可见

### 3.3 状态与互动 ✅
- 三状态：心情/饱食/精力，0-100，下限 5（不会"饿死"）
- 惰性衰减：饱食 -4/h、精力 -3/h、心情每小时向 50 回归 2 点；**读取时补算，无调度器**
- 喂食 +30 饱食 +5 心情（日限 3）；休息 +40 精力（日限 2）
- 经验/等级：exp = level×100 升级；等级解锁高阶探险区域（蘑菇村 Lv3、月光湖 Lv5）

### 3.4 任务 ✅
- 日常×3：陪伴时光（对话×3 → 15exp）、细心照料（照料蛋×1 → 10 孵化值）、按时开饭（喂食×1 → 10exp）
- 成就×3：初次相遇（孵化 → 幸运符）、无话不谈（累计对话 50 → 金铃铛）、小小冒险家（首次冒险 → 30exp）
- DB 可配置（tasks 表，启动时幂等播种）

### 3.5 离线探险 ✅
- 触发：用户离线 > 30 分钟，**回来上线时补算**（惰性模拟，单次上限 8 小时 / 10 个行为 tick，每 tick 45 分钟）
- 行为引擎：纯规则零 LLM，性格加权选行为（探索/觅食/社交/玩耍/休息），天赋修正（夜行者/寻宝鼻/虹运已实装）
- 事件库：5 区域 × 34 条模板事件；日志由 LLM 一次性润色为叙事，**故障时降级模板不丢数据**
- 收获：经验 + 道具入背包
- ❓ **D5 离线模拟架构**：原 Sprint 3 计划上 Celery Beat 定时调度。**但单机版无推送需求，惰性模拟（回来补算）功能等价且零运维**；回归卡片前端已有。推荐：**砍掉 Celery Beat，保持惰性模拟**，Sprint 3 大幅瘦身

### 3.6 内容安全 ✅
- 输入命中敏感词 → 不调 LLM 直接兜底；输出流式滚动窗口检测 → 整段替换兜底
- 词表 MVP 小词库（约 15 词），上线前接审核 API（Sprint 4 评估）

## 4. Sprint 3/4 模块的需求定义（4.0 已实现，4.1/4.2 部分完成，4.3-4.6 待开发）

### 4.0 诞生体验升级：问答引导 + 动态专属宠物（Sprint 3）— 2026-08-09 新增

> **实现状态（2026-08 中旬核对）：✅ 已实现**。问答(6 题, 已定稿入库 `gamedata.py QUIZ_QUESTIONS`)、QuizBias 注入种子生成、孵化后台生图任务、IP 转译、画风路由、精灵表管线（生成→网格切帧→防吃白毛→对齐→QC→manifest）、前端 QuizView/序列帧播放/SVG 降级均已落地；有单测（test_quiz/test_birth/test_petgen）与真实产物（`backend/static/pets/6/`，idle/wave 双动作 QC 通过、0 空洞）。
> ⬜ 未实现：降级链中的「i2i 逐帧补」备用环节（当前降级 = 重试 ≤2 → 预制 SVG）；无其他遗留。
> **临时方案（2026-08-15）**：生图套餐不可用期间，`PETGEN_MODE=reuse` 让孵化跳过生图 API，直接复用素材库 `backend/static/pets/_library/` 的已有形象（复制帧序列+manifest，状态置 ready）；live 模式生图失败时也会自动兜底复用。套餐恢复后把 `PETGEN_MODE` 改回 `live` 即可。

**需求**：用户首次使用时回答几个小问题；答案影响宠物的性格、物种与外观；孵化诞生时生成这只宠物的**专属动态形象**——不只是静态图，而是一只会眨眼、摆耳朵的活物（参考 Codex 宠物生成）。

**技术路线：单图精灵表 + 程序切帧（负责人拍板，2026-08-09 实测通过，对照 Codex 做法）**

```
1 次调用生成 sprite sheet(一张图含 8 个关键帧, 4列2行, 白底)
  → 连通域分割(每个角色实例是独立连通块, 不依赖网格对齐)
  → 质检(块数=8 且面积无离群, 不合格自动重生成)
  → 逐块抠图(边缘洪泛) → 对齐归一 → PNG 序列帧动画
```

**帧设计（v2 迭代，解决"3 帧太卡 + 瑕疵帧"反馈）**：8 帧 4×2 网格，姿势设计为**渐变序列**而非差异动作——上排眨眼渐变（睁眼→半闭→闭眼→半闭），下排头部微动（左倾/耳朵动/右倾/回正）；复杂姿势（如尾巴高翘）易出 AI 瑕疵（多尾巴），姿势全部从简。播放序列 `0,1,2,3,0,0,4,0,5,0,6,0,7,0`（130ms/帧）= 眨眼 + 头部微动的自然待机。实测 8 连通块干净切分、零瑕疵。

**方案选型记录**：视频（seedance）token 7 倍、循环有接缝、镜头漂移 → 弃；多图 i2i 逐帧生成（3 次调用）一致性够但贵 3 倍 → 降级为备用；**单图精灵表 1 次调用 16k tokens ~20s，单次生成内角色一致性天然最好** → 采用。备用方案的用途：精灵表切分失败时重试，或未来做复杂动作（吃/睡/走）时定向补帧。

**实测结论（2026-08-09）**

| 环节 | 方法 | 结果 |
|------|------|------|
| 精灵表生成 | `POST /api/plan/v3/images/generations`，`doubao-seedream-5.0-lite`，prompt 见下 | ✅ ~20s，16384 tokens（**8 帧量**），姿势顺序正确，角色一致，零瑕疵 |
| 自动切帧 | **网格单元为主**（按 4×2 均分画布，格内白底洪泛去背景，保留格内全部前景——动作帧的分离肢体不丢）+ 连通域质检辅助 | ✅ 两种风格验证：插画风（连通域亦可）、像素风（必须网格法，分离爪子会被连通域当噪点） |
| 风格适配 | 插画风：alpha 高斯羽化 + LANCZOS 缩放；**像素风：硬边 alpha + NEAREST 缩放**（保留像素锐利度） | ✅ 像素风招手验证通过 |
| **防吃白毛三件套** | ① 白底 mask 先 `binary_opening` 腐蚀 2px 断细桥再洪泛（防白毛经 JPEG 噪点桥被吃）② `binary_fill_holes` 填充闭合空洞 ③ **裁剪拼贴后再做一次画布级 fill_holes + 空洞数=0 验证**（有些通道裁剪后才闭合） | ✅ 8 帧 0 空洞（2026-08-09 用户发现嘴部透明洞后修复） |
| 演示封装 | GIF 仅作演示：帧必须扁平化到白底再合成（GIF 1 位透明 + Pillow 差分编码会导致脸部闪烁）；正式产品用 PNG 序列无此问题 | ✅ |
| **帧质检** | 块数必须 = 8 且各块面积在 0.5-2× 中位数内（多尾巴/粘连/缺帧会导致离群） | ✅ 不合格自动重生成（重试上限 2 次，仍失败降级预制 SVG） |
| 抠图 | 逐块 alpha + 高斯羽化 | ✅ 白毛完好（⚠️ 全局白色阈值会把白毛抠掉，必须边缘连通域） |
| 对齐 | alpha 包围盒裁剪 → 等比缩放 → 底部居中锚定 512² | ✅ 消除帧间跳变 |
| 拼接 | PNG 序列前端 JS 帧切换（GIF 仅用于演示） | ✅ 155KB 演示 GIF |
| ⚠️ 存储 | TOS 预签名 URL **24h 过期** | 即时下载本地 `backend/static/pets/{pet_id}/` |
| ⚠️ prompt 约束 | 必须含："纯白色背景无草地无阴影无网格线""三个姿势大小一致间距均匀" | 弱约束 → 草地背景/格子粘连，切分失败 |

精灵表 prompt 模板（物种/颜色/风格词由问答结果注入）：
> 一张游戏角色精灵表(sprite sheet), 4列2行均匀排列8个动画关键帧, 同一角色的待机动画渐变序列, 按从左到右、从上到下顺序: 第1帧睁眼自然微笑, 第2帧眼睛半闭, 第3帧闭眼微笑, 第4帧眼睛半闭, 第5帧睁眼头微微向左倾, 第6帧睁眼双耳微微竖起, 第7帧睁眼头微微向右倾, 第8帧睁眼自然微笑与第1帧相同. 角色是{外观描述}, {风格词}. 8个关键帧大小一致、姿势只有细微差别、风格完全一致、间距均匀互不重叠, 纯白色背景, 无草地无阴影无网格线无编号文字无任何环境元素

**每只宠物生成成本**：**1 次调用、~20s、16k tokens**（plan 套餐定额内，近乎免费）。诞生流程：孵化点击 → 蛋壳动画播放期间后台生成 → 未完成则先展示"正在成形"态 → 完成后诞生卡亮相。

**问答要素设计**（覆盖负责人要求的维度，5 题）

| 题 | 维度 | 影响 |
|---|------|------|
| Q1 你的理想周末 / 朋友眼中的你 | 性格 | 性格五维倾向（+种子随机微调） |
| Q2 喜欢的动物或事物 | 物种 | 物种倾向（可映射池内物种；自由描述经 LLM 转译为外观词） |
| Q3 喜欢的画风 | 风格 | 生图风格词（选项制：Q版萌系/水彩童话/国风水墨/像素复古等） |
| Q4 喜欢的 IP 形象（游戏/动漫/神话角色皆可） | 参考 | **LLM 特征转译**：把 IP 名转译为外观特征描述（如"皮卡丘"→"黄色圆润小家伙、闪电形尾巴"），转译后的描述进 prompt——规避版权与审核风险，原始 IP 名不进生图 prompt |
| Q5 偏好的颜色氛围 | 颜色 | 颜色倾向 + 场景氛围词 |

**模块架构：可迭代的生成管线（负责人要求 2026-08-11）**

设计原则：**画风路由 + 策略注册表**。新增画风/动作 = 加配置，不改核心代码。

```
                    ┌─ StyleProfile 注册表(按画风路由) ─┐
问答答案 → PromptBuilder → Ark生成 → 落盘原始图+参数 → Segmenter → CutoutProcessor
        (风格词/约束词)      (重试)    (关键!见下)     (网格切帧)   (按画风: 阈值/羽化/缩放)
                                                              ↓
                                        manifest.json ← QC质检(按画风规则) ← Aligner对齐
```

**StyleProfile（每种画风一份配置）**：`prompt_style`（风格词）、`whitish_threshold`、`opening_iterations`、`feather_sigma`（0=硬边）、`resize_filter`（LANCZOS/NEAREST）、QC 规则（允许的空洞数/面积方差）。初始两个 profile：`illustration`（羽化+LANCZOS）、`pixel`（硬边+NEAREST）——参数就是这两天实测定型的值。

**ActionTemplate（每种动作一份配置）**：帧数、每帧姿势描述、播放序列、帧间隔。初始：`idle_8`（眨眼+微动）、`wave_8`（招手）。后续 `eat`/`sleep`/`happy_jump` 等同理。

**可迭代性的三个支点**：

1. **原始图 + 全参数落盘**（`pets/{id}/raw_sheet.jpg` + `gen_params.json`）——后处理算法迭代时**离线重跑即可，零 token 成本**（本次实验中 pixel 修复就是复用原图重跑后处理）
2. **prompt 版本号**：每个 profile 的 prompt 模板带 `prompt_version`，写入 manifest；效果优化后可按版本筛选旧宠物重新生成
3. **金样本回归**：`docs/demo/` 保留各画风的验收样本，管线改动后重跑对比，防劣化

**manifest.json**（每宠物一份，前端按它播动画）：
```json
{"style": "pixel", "prompt_version": "pixel-v1",
 "actions": {"idle": {"frames": 8, "sequence": [0,1,2,3,0,0,4,0,5,0,6,0,7,0], "frame_ms": 130},
             "wave": {"frames": 8, "sequence": [0,1,2,3,4,5,6,5,4,5,6,7], "frame_ms": 140}},
 "qc": {"holes": 0, "retries": 0}}
```

**降级路由（已实现部分）**：精灵表生成失败/质检不过 → 重试（≤2）→ 预制 SVG + CSS 动效（前端 PetSprite 自动降级）。「i2i 逐帧补」环节当前未实现，留作未来复杂动作（吃/睡/走）的定向补帧手段。

**素材用途与降级链（精灵表方案版）**

| 素材 | 用途 | 降级 |
|------|------|------|
| 帧序列 PNG×8（透明底 512²，idle/wave 各一套）+ manifest.json | 首页待机/招手动画（PetSprite 按 manifest 播放），叠加 CSS 呼吸微动效；第 1 帧可作诞生卡/头像主帧 | 生成/质检失败 → 重试 ≤2 → 预制 SVG |
| 原始精灵表 + gen_params（落盘） | 后处理算法迭代时离线 reprocess，零 token 成本 | — |
| 预制 SVG | 最终兜底 | — |

**其他规则**：天赋/技能仍由种子随机（保留不可刷的惊喜感）；每用户仅诞生时生成一次；按《AI 生成合成内容标识办法》，诞生卡与档案页需带"AI 生成"标识。

| # | 题目 | 选项 | 影响 |
|---|------|------|------|
| Q1 | 周末的理想过法？ | A. 约朋友去热闹的地方（外向+开放）<br>B. 一个人探索没去过的角落（开放+内向）<br>C. 宅在家睡到自然醒（情绪稳定+低外向）<br>D. 把没做完的事安排妥当（尽责+） | 性格五维倾向 |
| Q2 | 朋友一般怎么形容你？ | A. 话多热情小太阳（话痨）<br>B. 安静但靠谱（高冷）<br>C. 戏很多的开心果（戏精）<br>D. 温柔好脾气（吃货/亲和系） | 性格标签倾向 |
| Q3 | 希望它是什么小家伙？ | A. 狐狸系 B. 猫咪系 C. 兔兔系 D. 狗狗系 E. 交给缘分（随机） | 物种倾向（映射物种池；稀有层仍锁） |
| Q4 | 喜欢什么画风？ | A. 手绘童话插画风（illustration）<br>B. 复古像素游戏风（pixel）<br>C. 交给缘分（随机） | **StyleProfile 路由**（仅放出已验证画风，新画风验证后再加） |
| Q5 | 希望它是什么色系？ | 快捷选项：A. 暖橙 B. 翠绿 C. 黛蓝 D. 樱粉；**支持手动输入**（如"薄荷绿""奶茶色"） | 宠物配色 + 外观氛围词 |

**映射规则**：性格 = 问答倾向 + 种子随机微调（±15）；物种按倾向从 common 池抽；天赋/技能仍纯种子随机；Q6 转译在孵化时调用一次（compact prompt，约 100 字符），失败/超时则忽略该特征。**Q5 手动输入处理**：限 10 字符，过现有敏感词过滤器，以"{输入}色系"形式进 prompt；命中敏感词或为空则回退到快捷选项默认值（暖橙）。

### 4.1 回归体验（Sprint 3）— 「它活着」的关键触点

### 4.3 宠物档案页（Sprint 4 初）— ❓ D4

- 内容：名字/物种/稀有度/等级经验条/性格五维数值+标签/天赋/技能/背包道具
- **推荐：做简单文字+标签版，不做雷达图**（雷达图 V1.x）。这是"它独一无二"的载体，目前用户看不到自己的宠物有什么天赋技能

### 4.4 新手引导（Sprint 4）

- 首次注册后 3 步浮层：①这是你的蛋 ②照料它（点一次） ③每天照料，2-3 天后孵化
- 实现：前端引导组件 + localStorage/服务端标记 `guide_done`，不做复杂编辑器

### 4.5 数据埋点（Sprint 4）

- 指标（蓝图第 6 节）：冒险日志查看率、次留/7 留、孵化完成率、日均对话轮次、单用户 LLM 成本
- 实现：events 落 PostgreSQL 单表（user_id/event/ts/props）+ 统计 SQL 脚本；LLM 成本从 usage.jsonl 算。**不引入第三方埋点 SDK**

### 4.6 性能与安全加固（Sprint 4）

- 对话首 token < 2s：**换标准 Ark key + 豆包模型**（用户申请，backend/.env 注释有切换步骤）
- 安全：敏感词库扩充 + 审核 API 接入评估（输出评估报告，接入与否看成本）
- 稳定性：修复 pytest 全量挂起问题；代码推远程仓库
