## 0. 设计红线（已拍板，不可违反）

| # | 红线 | 含义 |
|---|------|------|
| R1 | **纯牵挂，零损失厌恶** | 没有任何"不回来就亏/被拿走"的机制；"失去"只以消耗/交换/赠予的叙事形式存在 |
| R2 | **交换永不降级** | 交换所得品级 ≥ 带出品级；系统不得在用户离线时替用户做亏本决定 |
| R3 | **传说品级不可消耗** | 传说品不出现在口粮属性上；收藏品永不丢失 |
| R4 | **不允许加速** | 旅行时长不可付费/操作缩短 |
| R5 | **陌生化转述** | 种子角色/地点在日记中以宠物视角描述，不出现真实人物/作品原名（沿用 Q6 IP 转译方法论） |

## 1. 目标用户与心理模型

面向 **抽卡 + 集邮 + 养成 + 轻游戏** 群体（参照：旅行青蛙 / QQ农场 / 月兔旅行）：

- 爽点核心 = **归来开卡**（每日 1-2 次迷你抽卡：品级光效 + NEW! 标记 + 图鉴进度）
- 留存核心 = **图鉴完成度长尾** + **种子包持续上新**（每波新包 = 一次回归理由）
- 情绪核心 = 牵挂（等待）+ 认出（种子共鸣）+ 被记住（对话/首发现冠名）

## 2. 术语

| 术语 | 定义 |
|------|------|
| 种子(Seed) | 一次旅行的叙事单元：地点背景 + 角色卡 + loot 表 + 事件卡组 + 氛围词，打包定义 |
| 种子包(Pack) | 种子的分组（图鉴分组/上新运营单元），如"山海经·东" |
| 基调(Flavor) | 一趟旅行的主旋律，先抽基调再围绕它抽事件 |
| ItemDef | 物品静态定义（内容文件）；发现状态（首发现者/时间）在 DB |
| 行囊(Loadout) | 出门前打包的 3 槽位：口粮×1 + 伴手礼×1 + 护身符×1 |

## 3. 种子模型

```yaml
# 单个种子（内容文件，版本化，随代码提交）
seed:
  id: myth:moon_palace          # 命名空间: 线:id
  pack: myth_shanhaijing_east   # 所属包（图鉴分组）
  name: 月宫                    # 内部名（不直接外露给玩家, 玩家看到的是陌生化描述）
  min_level: 1
  time_gate: null               # 或 {"festival": "mid_autumn", "window_days": 3}
  background: |                 # 给 LLM 的背景卡（成文时注入）
    终年桂花香的月面宫殿, 白玉台阶, 云雾缭绕…
  cast:                         # 角色卡
    - id: npc:jade_rabbit
      desc_words: 捣药的白兔, 红眼睛, 围裙    # 陌生化锚点: 视觉+感官, 不给真名
      interactions: [receive_gift, exchange]
    - id: npc:wugang
      desc_words: 砍一棵永远砍不倒的树的高大男人
      interactions: [meet_character]
  loot_table:                   # 物品产出表: item_id → 权重(品级隐含在 ItemDef)
    - {item: osmanthus_cake, weight: 40}
    - {item: moonstone, weight: 15}
    - {item: moon_herb, weight: 8}
  event_deck:                   # 事件卡组, 按基调分类
    encounter: [...]            # 际遇回可用
    food: [...]                 # 美食回可用
    scenery: [...]              # 闲逛回/留白回通用
  atmosphere: 桂花香/银白色/安静   # 氛围词(注入 LLM prompt)
```

**校验测试（内容进库的硬门槛）**：结构合法 / 引用的 item、npc id 全部存在 / 事件卡组基调标签合法 / 全文本过敏感词 / loot 权重和=100。

## 5. 物品体系

### 5.1 ItemDef 字段

```yaml
item:
  id: osmanthus_cake
  name: 桂花糕                 # 玩家可见名(物品名可直接显示, 地点/角色名才需陌生化)
  desc: 带着月宫桂花香的糕点
  rarity: common               # common(常见) / rare(稀有) / epic(传说)（Q1 已拍板: 用最常见文案）
  attr: food                   # food(口粮) / gift(伴手礼) / charm(护身符) / antique(古董)
  appearance: 菱形白糕, 缀金色桂花   # 生图用外观描述词
  image: /static/items/osmanthus_cake.png
  source_seed: myth:moon_palace
```

### 5.2 品级 × 属性矩阵

| | 口粮 food | 伴手礼 gift | 护身符 charm | 古董 antique |
|---|---|---|---|---|
| 常见 common | ✅ 主力 | ✅ 主力 | ✅ | ✅ |
| 稀有 rare | ✅ 封顶 | ✅ | ✅ | ✅ |
| 传说 epic | ❌（R3） | ✅ | ✅ | ✅ |

### 5.3 物品图片（预生成，不走运行时）

- 内容进库时批量生成：单帧道具图标，统一软萌插画风，**不跟随宠物画风**（已拍板：图鉴是社交货币，同物同图）
- prompt 模板："单个游戏道具图标，{appearance}，居中，纯白背景无阴影"；复用 petgen 的白底抠图/QC/落盘
- 落盘 `backend/static/items/{item_id}.png`，随代码提交；生成失败 → QC 拦截在入库前，运行时零失败

### 5.4 存储两层

| 层 | 内容 | 位置 |
|---|---|---|
| ItemDef 静态定义 | 见 5.1 | 内容文件（配置即代码，版本化+单测） |
| 发现状态 | first_discovered_by(user_id) / first_discovered_at | DB 表，启动时从内容文件幂等播种，运行时仅回填一次 |
| Inventory | item_id 引用 + count + acquired_at + acquired_zone + acquired_via(forage/exchange/gift) | pet.inventory JSON 升级 |

**存量迁移**：旧 inventory 为名字字符串 → 一次性映射名字→item_id，映射失败归入"失落的纪念品"兜底条目。

## 6. 行囊系统

- **背包（收藏库）无上限**；**行囊 3 槽位**：口粮×1 + 伴手礼×1 + 护身符×1，每格可空
- 空手出门合法，不惩罚；打包出门产出更好（正向表达，非负向惩罚）
- 消耗品产出/消耗比 ≥ 1.5:1（数值表定档）

## 7. 旅行引擎

### 7.1 一趟旅行的流程（确定性边界：收获/品级/消耗规则引擎定，措辞 LLM 定）

```
选种子(Q6偏好加权+等级门控+时间门控) → 抽基调(性格加权) → 从种子事件卡组按基调抽事件
→ 结算(loot品级抽取/口粮消耗/交换/赠予) → LLM 带种子背景成文(1次lite, 降级模板) → AdventureLog
```

### 7.2 基调表（10 种，性格加权）

| 基调 | 内容 | 基准权重 | 性格加成 |
|------|------|---------|---------|
| 际遇回 | 遇到种子角色 | 12% | 外向↑ |
| 交友回 | 遇到动物伙伴 | 12% | 外向↑、胆小↓ |
| 收集回 | loot 探索收获 | 18% | 开放↑ |
| 美食回 | 品尝当地吃食 | 10% | 吃货↑↑ |
| 学艺回 | 观摩学到小把戏 | 8% | 尽责↑ |
| 助人回 | 帮了谁小忙 | 10% | 亲和↑ |
| 惊险回 | 虚惊一场，**安全解决零损失**（R1） | 8% | 稳定高↑、胆小↓ |
| 寻宝回 | 高品级产出 | 7% | 寻宝鼻↑ |
| 闲逛回 | 风物体验 | 10% | — |
| 留白回 | 什么都没干睡一觉回来，**保底小物** | 5% | 稳定高↑ |

## 8. 交换系统（L1 单机版）

- 交换对象 = 种子角色卡（`npc:*`），如"在火焰山用团扇换到芭蕉形叶子"
- 交换所得品级 ≥ 带出品级（R2）；换回什么未知（保留开卡感）
- 是否发起交换由宠物性格决定；不交换=原样带回（性格表达，文案兜底成萌点）
- provider 接口隔离：`resolve_exchange(gift, seed) -> (counterpart_ref, received_item)`，L1 从种子 cast 选；未来 L2 真人撮合时替换实现，调用方不变

## 9. 首发现（冠名）

- 粒度：物品定义级；字段 `first_discovered_by(user_id)` / `first_discovered_at`，发现即检查回填
- 纯荣誉徽章，**无实质加成**（防竞速焦虑，守 R1）
- 单用户期呈现为"你的团团于 X 首次发现"；多用户上线自动升级为全服冠名

## 10. 社交就绪接缝（只留缝，不建表）

1. 所有"引用角色"的字段 = 带类型复合引用：`npc:yutu` / `pet:42` / `user:7`，禁止裸 ID
2. "离线期间发生的事"统一为事件 feed；归来信件是 feed 的一种（`travel_returned`），未来"来访/收礼"为新事件类型
3. 对外展示名一律经 `display_name()` 函数（现返回 username，未来读 display_name 字段）
4. 明确不建：好友表/互访表/挂单表；不开 `/api/social/*`

## 11. 页面与操作预期表（**验收准绳**：每个操作 → 明确的预期结果）

### 11.1 主页（Home）

| # | 用户操作 | 预期结果 |
|---|---------|---------|
| H1 | 打开 App，宠物在家 | 显示宠物序列帧动画；**环形贴边 UI**（规范 v1.1，参考旅行青蛙/农场）：顶左宠物信息木牌（名字/等级/性格标签）、左下大木牌「打包行李」、右下木牌「收藏」（图鉴+日记）；品牌大标题在宠物出现后隐去。**布局红线：任何 UI 元素不得遮挡宠物形象**（2026-08-23 拍板；对话入口已移出 MVP，见 §14 Q5） |

| H5 | 关闭信件 | 回到 H1 状态；本次收获已入背包与图鉴；便签信消失 |

## 12. 全局验收标准

- 单元测试：种子内容校验（第 3 节）、基调权重归一、品级×属性约束（R3）、交换不降级（R2）、首发现回填、行囊槽位规则

- LLM 环节故障 → 模板降级，数据不丢（沿用现有红线）

## 13. 内容生产流水线
