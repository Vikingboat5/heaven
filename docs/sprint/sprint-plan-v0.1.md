## 单人容量校准说明

原规划（1-3 人，6-8 周）共约 54 人天。单人全栈需额外承担：前后端上下文切换、DevOps、设计、测试全部工作，有效产能约为专职的 70-80%。

**校准策略：范围收缩 + 周期延长双管齐下**
- 周期：6-8 周 → **10-12 周**（含 1 周缓冲）
- 收缩项（详见 PRD 第 5 节）：
  - 长期记忆：向量检索 → 结构化事实抽取（省 ~2 天，V1.1 再升级）
  - Web Push → 站内通知（省 ~1.5 天）
  - 宠物互访精简（省 ~1 天）
  - 砍掉结伴冒险预研（省 ~2 天）
  - 不做管理后台，配置走 DB 表 + 脚本（省 ~2 天）
  - UI 从简：CSS 动画 + 预制素材，不引入 PixiJS（省 ~2 天）

## 风险管理（单人特别版）

- **进度风险**：每周五自评进度，偏差 > 20% 触发裁剪（裁剪顺序：T3.6 亲密度 → T3.2 互访 → T2.3 事实记忆降级为手工标签）
- **单点风险**：代码每日提交（git init 后推送到私有远程仓库，防本地磁盘故障）
- **精力风险**：前后端切换以「天」为单位批处理，避免半天一切换
- **范围蔓延**：任何新想法先记入 V1.x  backlog，MVP 期间不插入
