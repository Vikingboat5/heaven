## 1. 产品概述

### 1.1 一句话定位
一个以「宠物 Agent」为核心的游戏化 AI 应用：用户孵化宠物蛋，获得一只有随机技能、天赋和独特性格的 AI 宠物；它能与主人自然对话，主人不在时自主探险，还能和好友的宠物社交、结伴冒险。

### 1.2 核心价值主张
传统电子宠物是「预设脚本的玩具」，本产品的宠物是「有记忆、有性格、有自主行为的 Agent」——每只宠物都是独一无二的生命体，情感连接是留存的根本驱动力。

### 1.3 目标用户
国内 18-35 岁喜爱宠物/养成类游戏的用户。18+ 定位，标准内容安全等级。

### 1.4 平台
Web PWA（桌面与移动浏览器自适应，可添加到主屏）。

---

## 2. 核心玩法循环（Core Loop）

```
获取宠物蛋 → 做任务孵化 → 宠物诞生（随机技能/天赋/性格）
    ↑                                      ↓
    ↑                              日常互动（对话/喂养/任务）
    ↑                                      ↓
    ↑                              宠物成长（等级/新技能）
    ↑                                      ↓
    └──── 奖励与收获 ←── 自主探险（主人离线时）←── 社交（好友宠物互动）
```

设计要点：主人离线时宠物「活着」并留下故事，主人上线后「回看冒险日志」是最强回访钩子。

## 3. 功能需求

### S1 宠物蛋系统（MVP）

**用户故事**
- US-1.1 作为新用户，我希望注册后获得第一枚宠物蛋，以便立即开始游戏。
- US-1.2 作为用户，我希望通过完成任务积累孵化进度，以便孵化过程有目标感和成就感。
- US-1.3 作为用户，我希望宠物蛋有不同稀有度，以便有收集和追求的动力。

**功能规格**
| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F1.1 | 蛋的获取 | 注册赠送×1；任务奖励；好友赠送（V1.1） | P0 |
| F1.2 | 孵化值机制 | 完成任务获得孵化值，满值（100点）触发孵化 | P0 |
| F1.3 | 稀有度 | 普通/稀有/传说三档，影响天赋池与外观 | P0 |
| F1.4 | 蛋的状态展示 | 孵化进度条 + CSS 阶段动画（晃动/裂纹） | P1 |

**验收标准（DoD）**
- 新用户注册后 30 秒内获得宠物蛋并看到孵化引导
- 每类任务奖励的孵化值可配置（数据库配置表，单人开发不做管理后台）
- 稀有度概率可配置、可审计（服务端随机，种子可复现）

---

### S2 随机生成系统（MVP）

**用户故事**
- US-2.1 作为用户，我希望宠物孵化出来时有随机的技能和天赋，以便我的宠物是独一无二的。
- US-2.2 作为用户，我希望稀有蛋能孵出更强的天赋，以便稀有度有意义。

**功能规格**
| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F2.1 | 物种/外观生成 | 从物种池随机 + 配色变体（MVP 用预制 2D 素材组合，不做程序化生成美术） | P0 |
| F2.2 | 天赋生成 | 1-2 个被动天赋（如「夜行者：夜间探险收益+20%」），稀有度影响池子 | P0 |
| F2.3 | 技能生成 | 初始 1 个主动技能，成长解锁（技能池分探险/对话/社交/生产四类） | P0 |
| F2.4 | 种子化随机 | 全部随机基于服务端种子，可复现、可审计、防刷 | P0 |

**验收标准**
- 同一 seed 重复孵化结果完全一致（单元测试覆盖）
- 各稀有度天赋分布符合配置表（万次模拟分布偏差 < 1%）

---

### S3 性格系统（MVP）

**用户故事**
- US-3.1 作为用户，我希望我的宠物有独特性格，以便它的言行让我感到「它是活的」。
- US-3.2 作为用户，我希望能查看宠物的性格画像，以便理解它的行为倾向。

**功能规格**
| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F3.1 | 性格模型 | 大五人格简化 5 维（外向/亲和/尽责/情绪稳定/开放，各 0-100）+ 1-2 个特殊标签（傲娇/话痨/胆小/吃货…） | P0 |
| F3.2 | 性格→对话 | 性格维度映射为 LLM system prompt 片段（语气、口癖、反应模式） | P0 |
| F3.3 | 性格→行为 | 性格影响行为权重：外向宠物更爱社交，开放宠物更爱探险 | P0 |
| F3.4 | 性格可视化 | 雷达图 + 标签展示 | P1 |
| F3.5 | 性格演化 | 重大事件轻微改变性格维度 | P2（V1.2） |

**验收标准**
- 给定性格配置，对话输出风格可被人工盲测区分（内向 vs 外向，准确率 > 80%）——Sprint 0 POC 验证
- 性格维度对探险/社交行为倾向的影响在模拟数据中可观测

---

### S4 对话系统（MVP，LLM 驱动）

**用户故事**
- US-4.1 作为用户，我希望和宠物自由对话，以便建立情感连接。
- US-4.2 作为用户，我希望宠物记得我们之前聊过的重要事情，以便对话有连续性。
- US-4.3 作为用户，我希望宠物的心情会受我的互动影响，以便我的行为有意义。

**功能规格**
| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F4.1 | 实时对话 | LLM 流式输出（SSE），条件化上下文 = 性格 + 当前状态（心情/饱食/疲劳）+ 记忆 | P0 |
| F4.2 | 短期记忆 | 当前会话上下文窗口管理（最近 N 轮） | P0 |
| F4.3 | 长期记忆 | **单人开发简化方案：结构化事实抽取**（小模型异步从对话提取「主人名字/喜好/重要事件」存入事实表，对话时注入）。向量语义检索（pgvector）延至 V1.1 | P0（简化版） |
| F4.4 | 情绪系统 | 心情/饱食/疲劳三状态，互动改变状态，状态影响对话与行为 | P0 |
| F4.5 | 主动搭话 | 宠物在特定触发下主动发起对话（如主人上线时） | P1 |
| F4.6 | 内容安全 | 输入过滤 + 输出过滤 + 敏感话题兜底话术 | P0 |

**验收标准**
- 对话首 token 延迟 < 2s（流式）
- 宠物能正确引用主人此前告知的重要信息（事实表抽取准确率人工抽检 ≥ 85%）
- 安全测试集（涉政/色情/暴力/诱导）拦截率 100%，兜底回复不破坏角色感

---

### S5 自主探险系统（MVP，离线 Agent）

**用户故事**
- US-5.1 作为用户，我希望我不在的时候宠物会自己去探险，以便它有「自己的生活」。
- US-5.2 作为用户，我希望上线后能看到宠物的冒险日志，以便有惊喜感和回访动力。
- US-5.3 作为用户，我希望宠物探险能带回收获，以便离线时间有价值。

**功能规格**
| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F5.1 | 离线触发 | 主人离线超阈值（30 分钟）后，服务端调度器接管宠物行为 | P0 |
| F5.2 | 行为引擎 | 基于性格 + 需求状态 + 天赋的决策（探索/休息/觅食/访友），**纯规则驱动，零 LLM 成本** | P0 |
| F5.3 | 冒险事件库 | 模板化事件（MVP 30+ 条），按区域与等级抽取 | P0 |
| F5.4 | 冒险日志 | 一次离线周期结束后，小模型一次性将事件序列润色为叙事日志（批量调用，成本可控） | P0 |
| F5.5 | 探险收获 | 经验/道具/故事碎片，放入宠物背包 | P0 |
| F5.6 | 回归通知 | **站内通知**（上线时展示「你的宠物回来了，带回了xxx」）。Web Push 延至 V1.1（iOS PWA 推送支持差，单人开发不投入） | P0（站内） |

**验收标准**
- 主人离线 8 小时后上线，能看到连贯的冒险日志（3-8 个事件）
- 单宠物单日离线模拟 LLM 成本 ≤ 预算上限（Sprint 0 成本实测确定数值）
- 模拟服务故障时降级为纯模板日志，不丢数据

---

### S6 社交系统（MVP 精简版）

**用户故事**
- US-6.1 作为用户，我希望加好友后我们的宠物能互相认识，以便有社交话题。
- US-6.2 作为用户，我希望宠物能和好友的宠物结伴冒险并生成共同的故事（V1.1）。

**功能规格**
| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F6.1 | 好友体系 | 用户加好友（搜索 ID/分享链接）→ 双方宠物互相可见 | P0 |
| F6.2 | 宠物互访（精简） | 宠物可访问好友宠物并留下互动记录（打招呼）。赠礼延至 V1.1 | P1 |
| F6.3 | 宠物亲密度 | 互动积累亲密度 | P1 |
| F6.4 | 结伴冒险 | 双 Agent 轮流对话生成冒险故事 | P2（V1.1） |

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 对话流式首 token < 2s；页面加载 < 3s |
| 成本 | 单活跃用户日均 LLM 成本 ≤ 预算上限（Sprint 0 实测确定）；单宠物日配额熔断 + 全局闸口 |
| 安全 | 输入输出双向内容过滤；18+ 标准等级；数据加密存储 |
| 可靠性 | 离线模拟服务故障可降级；宠物状态数据每日备份 |
| 可观测 | LLM 调用量/成本/延迟埋点（结构化日志，单人开发不引入重型 APM） |
| 合规 | 国内上线：ICP 备案、生成式 AI 算法备案、内容审核机制（上线前处理，不阻塞开发） |
| 商业化预留 | 对话轮次/探险次数的配额体系预留付费墙点位（MVP 不实现付费） |

## 5. MVP 范围界定（单人全栈校准版）

**MVP 包含**：S1-S5 全部 P0 + S6 的 F6.1；S4 长期记忆为结构化事实简化版；S5 通知为站内版

**V1.1**：结伴冒险（双 Agent）、向量语义记忆（pgvector）、Web Push、宠物赠礼/赠蛋、宠物互访深化
**V1.2+**：性格演化、宠物繁殖、公会、UGC 冒险地图、内购系统

**明确不做（MVP 阶段）**：宠物对战 PVP、区块链/NFT、语音对话、3D 画面、管理后台（用配置表+脚本替代）、程序化美术生成
