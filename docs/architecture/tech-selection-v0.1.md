## 1. 架构总览

```
┌────────────────────────────────────────────────────────────┐
│  前端: Vue3 + Vite + TS + Pinia + vue-router (PWA)          │
│  - 实时对话: SSE (流式)                                     │
│  - UI: 简洁 CSS 动画 (MVP 不引入 PixiJS/重型组件库)         │
└──────────────────────┬─────────────────────────────────────┘
                       │ HTTPS / SSE
┌──────────────────────▼─────────────────────────────────────┐
│  后端: Python FastAPI (单体应用, 模块化包结构)              │
│  ├─ api/        路由层 (auth / pet / dialogue / adventure)  │
│  ├─ core/       宠物Agent引擎: persona构建 / 行为引擎       │
│  ├─ llm/        LLM网关: Ark客户端 + 预算熔断 + 用量记录    │
│  ├─ models/     SQLAlchemy 模型                             │
│  └─ services/   业务服务 (孵化/生成/任务/社交)              │
├────────────────────────────────────────────────────────────┤
│  离线模拟: Celery + Redis (Beat 定时扫描离线宠物)           │
├────────────────────────────────────────────────────────────┤
│  数据层: PostgreSQL 16 (业务+事实记忆) / Redis 7 (缓存+队列)│
│  本地开发: docker-compose 一键起 PG+Redis                   │
├────────────────────────────────────────────────────────────┤
│  LLM: OpenAI兼容协议抽象 → 火山Ark (豆包)                  │
│  分层: 实时对话=中档 / 日志润色+事实抽取=小档 / 行为决策=无 │
└────────────────────────────────────────────────────────────┘
```

**单体仓库（monorepo）**：`frontend/` + `backend/` + `scripts/` + `docker-compose.yml`，单人维护一个仓库，减少切换成本。

## 2. 技术选型明细（单人全栈原则）

### 前端：Vue3 + Vite + TypeScript + Pinia + vue-router + vite-plugin-pwa

| 考量 | 说明 |
|------|------|
| 减少上下文切换 | Vue SFC 单文件组件（template/script/style 同文件），比 React 少文件跳转 |
| 中文生态 | 文档/社区中文资源最丰富，符合开发者环境 |
| AI 辅助编码 | Vue3 + TS 是主流 AI 训练语料高覆盖栈 |
| 官方全家桶 | router/Pinia 官方维护，决策成本低 |
| PWA | vite-plugin-pwa 零样板生成 SW 与 manifest |

不引入：大型 UI 组件库（MVP 界面简单，自建轻组件 + 原子 CSS 即可，避免被组件库风格绑架）；PixiJS（延至需要复杂动画时）。

### 后端：FastAPI + SQLAlchemy 2.0 + Alembic + Celery + Redis

| 考量 | 说明 |
|------|------|
| LLM 生态 | Python 是 LLM 工具链母语 |
| 异步原生 | SSE 流式对话、并发 LLM 调用无额外成本 |
| 类型友好 | Pydantic 模型与前端 TS 类型心智一致，AI 生成代码质量高 |
| Celery | 离线模拟调度的标准答案，Beat 定时 + Redis broker |

### 数据层
- **PostgreSQL 16**：全部业务数据 + 宠物事实记忆（结构化表）。pgvector 扩展预装但 MVP 不启用（V1.1 向量记忆）
- **Redis 7**：会话缓存、Celery broker、令牌桶限流、宠物实时状态、LLM 预算计数器

### LLM 网关设计（核心自研模块）

```python
# 分层路由 + 预算熔断 + 用量审计，业务代码不绑定供应商
LLMGateway
 ├─ chat(tier="standard", messages, persona)   # 实时对话: 豆包pro
 ├─ chat(tier="lite", messages)                # 日志润色/事实抽取: 豆包lite
 ├─ budget_guard(pet_id)                       # Redis日配额计数, 超额→降级
 └─ usage_log(...)                             # 每次调用记录 token/成本/延迟
```

**分层模型策略**：
| 场景 | 档位 | 模型（生产） | 说明 |
|------|------|------------|------|
| 用户实时对话 | standard | doubao-pro 系列 | 体验关键路径 |
| 冒险日志润色 | lite | doubao-lite 系列 | 批量异步，一次离线周期 1 次调用 |
| 事实抽取/摘要 | lite | doubao-lite 系列 | 低频异步 |
| 离线行为决策 | 无 | — | 规则引擎，零 token |

### Agent 框架
自研轻量 Agent 循环（persona + 记忆 + 状态机 + prompt 工程），不引入 LangChain 等重框架。核心约 500-800 行，完全可控、可调试。

## 3. 成本控制架构（R1 风险应对，本项目生死线）

**问题**：宠物离线自主行为 = 用户不在场也在消耗 token。

**三层防线**：
1. **行为决策零 LLM**：离线行为由规则引擎驱动（需求状态机 + 性格权重 + 随机事件表）
2. **叙事生成批量化**：一次离线周期只调 1 次 lite 模型润色整段日志
3. **预算熔断**：每宠物每日 token 配额（Redis 计数），超额降级为模板日志；全局日预算闸口

**Sprint 0 交付**：《成本基线报告》——模拟 100 宠物 × 1 天，实测 token 消耗，确定配额参数与免费用户对话轮次上限。

## 4. 内容安全架构（18+ 标准等级）

```
用户输入 → [敏感词过滤] → LLM(system prompt护栏) → [输出敏感词过滤] → 用户
                              │
                              └─ 拦截 → 兜底话术(保持角色感)
```

- MVP：本地敏感词库 + system prompt 护栏
- 上线前：接入火山/阿里云内容安全审核 API（合规要求）
