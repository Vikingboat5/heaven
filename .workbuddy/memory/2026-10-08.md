## 阅读 D:/heaven 项目（宠物乐园 Pet Paradise）

- 需求：用户要求通读这个游戏项目（session标签「小程序」，但项目本身是 Vue3 Web，不是小程序）。
- 结论摘要：
  - 产品灵魂「它活着」= 旅行青蛙式离线自主生活 + AI 对话。单机版一人一宠，社交砍到 V1.1。
  - 后端 FastAPI + SQLAlchemy2 + PostgreSQL/Redis；LLM 统一走 `app/llm/gateway.py`（tier=standard对话 / lite润色抽取，Redis 日配额 BudgetGuard，超额抛 BudgetExceeded 由业务降级）。
  - 旅行状态机在 `services/adventure.py::check_and_simulate`，惰性推进：离线≥45min自动出门 → 到 back_at 结算 → 行为引擎 `core/behavior.py` 纯规则零 LLM 抽事件/结算 → 仅 1 次 lite 调用润色信件 + 顺带输出「地点记忆卡」（pet_seed_memories，重访连续性，零额外调用）。
  - 内容配置化：`app/content/{seeds,items,animation_designs}.json`，`core/catalog.py` 加载即校验，失败抛 ContentError 不带病运行。
  - 前端 9 个视图 + PetSprite 序列帧组件（manifest.json 驱动，缺动作降级 SVG；帧密集时硬切不淡化——淡化机器本身是闪烁源）。
  - 文档体系很成熟：蓝图(最高准绳) / mvp-spec(唯一需求依据, v1.1) / seed-item-system-spec / ui-motion-guidelines(v1.3) / ADR-001~003 / animation-pipeline-spec。

  - ADR-003：对话因 UGC 合规风险移出 MVP，入口撤下但代码保留。

## 建立小程序转换工程 D:/heaven-miniprogram

- 需求：用户要求另起文件夹做小程序转换。用户反问了「选型看什么维度」「三种目录位置利弊」→ 说明用户在意决策依据而非直接给答案。
- 目录选型结论：**D:/heaven-miniprogram（与 heaven 平级）** —— 两者发布周期/审核流程不同，且能直接复用原地后端不复制代码。
- 技术选型：推荐 **uni-app (Vue3+TS+Pinia)**，与现有栈同源可平移；Taro(React)等于重写 4400 行；原生要手写 9 页。**关键岔路 = App 是否明确目标**（传统版 vs uni-app x）。
- 查证到的两个阻塞级问题（重要）：
  1. 🔴 **《人工智能拟人化互动服务管理暂行办法》2026-07-15 已施行**（网信办令第21号）。本项目有性格+情感信件+牵挂感，大概率落入「拟人化互动服务」。义务含 AI 身份提示、生成内容标识、连续使用每超 2h 提醒、依赖预警、算法备案。**注意：ADR-003 移出对话并不能规避，因为新规覆盖情感互动本身**。
  2. 🔴 **素材 149MB vs 小程序 20MB 上限**（主包≤2MB）。必须全部 CDN 化，与框架选型无关。
- 其他关键约束：小程序包体 2MB/20MB；SSE 不支持，需 `wx.request({enableChunked:true, responseType:'arraybuffer'})` + `onChunkReceived`，Nginx 须 `proxy_buffering off`；**游戏类目 vs 普通小程序是两套独立账号，AppID 不可互转，选错只能重新注册（注册前必须拍板）**；2026 年 Skyline 已成为新建小程序推荐标准但限制多，主项目 CSS 变量需实测。
- 后端好消息：**零改动复用**（FastAPI 原样），仅需加 `/api/auth/wx-login`（若改 wx.login 免注册）。
- 产出文件：`README.md`、`docs/feasibility/评估报告.md`、`docs/feasibility/合规风险备忘.md`、`docs/decision/ADR-MP-001-技术选型.md`。
- 建议路线：P0 合规先行（并行，最长周期）→ P2 先做最短链路 Demo（约 20% 工作量，验证后端复用/CDN/动画三个最大不确定性）→ 再决定全量投入。
