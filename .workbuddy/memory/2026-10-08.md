## 同日修正：CDN 不是必须的（我此前的结论被实测推翻）

- 用户追问"CDN 这个是必须的吗" → **实测后发现我之前的结论基于错误假设，已修正 ADR-MP-002**。
- **错误在哪**：我把 149MB 当作"全部是必须分发的预置素材"。实际构成：pets/28 单只 52MB(含 _anim_pending 13MB)、pets/29 12MB、pets/1 11MB、全是开发期中间产物(raw_sheet/preview/contact/实验目录 _video_probe/_smooth/_anim_pending/_library)，共 **43.8MB 纯垃圾**。且**帧序列是纯 PNG 未压缩**（单帧 180-240KB，对 512x512 纯色卡通帧异常大）。
- **实测压缩率**（Pillow q80，Python 3.11 的 PIL）：单帧 234KB → WebP 19KB(**8%**)；固定素材 26MB→4MB；宠物帧 13MB→1.2MB(91%)。整体 **647 文件 / 114.7MB → 15.6MB(压缩86%)**。
- **结论**：压缩后连全部 23 只宠物帧都能进包（15.6 + 代码 0.2 ≈ **15.8MB < 20MB**）→ **CDN 非必须**。省掉开对象存储+域名白名单整套运维。规模化后(宠物>40只或 +0.18MB/只触顶)再迁，`CDN_BASE` 已封装成常量，改一个值切换。
- **发现关键技术坑**：微信 `image` 组件 `webp` 属性**默认 false，官方文档明确"只支持网络资源"** → 包内 WebP 必须在 `<image>` 显式加 `webp` 属性，且必须真机验证。已加进 PetSprite.vue。
- 产出：`scripts/optimize_assets.py`（--check/--clean/--out 三模式，已跑通验证）；ADR-MP-002 改写为「素材压缩策略（CDN 非必须）」含修正记录；TODO B1 组重写；PetSprite 帧 URL 改 .webp；README 更新。复验 vue-tsc 通过 + build DONE。
- **方法论教训**：评估包体/迁移成本前必须先实测真实数据构成，别拿"总量"当"必须分发量"。压缩率这类数字实测一下（30秒）比推理可靠。
