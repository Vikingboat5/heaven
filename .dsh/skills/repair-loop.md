# 修复自检闭环协议 (Repair Loop)

> DSH 技能副本；Claude Code 用 `.claude/skills/repair-loop.md`（同内容）。修改时两处同步。

适用：用户报告 bug、请求修改功能、"修了还坏"、任何即将改动代码的任务。
**开始动手前必须先加载本协议**；违反协议的每一步都会直接回到上一轮事故的模式。

---

## 五步闭环

```
① 取证定位 → ② 留回退点 → ③ 最小修改+测试先行 → ④ 自验证(E2E) → ⑤ 验证通过才汇报
                                    ↑___________ 不过 → 回退/继续修 ←___________|
```

### ① 取证定位（禁止边猜边改）

- 先复现并定位**根因**，再动代码；排查方法见 `debug-playbook` 技能（证据阶梯）
- 输出一句话根因陈述："症状 X 的原因是 Y 层执行了 Z"，没有这句不动手

### ② 留回退点（动手前）

- `scripts/checkpoint.ps1` 留一个 git 回退点（无 git 时先 `git init`）
- 明确记录本次要改动的文件清单，改完逐个验证（改 N 个验证 N 个）

### ③ 最小修改 + 测试先行

- 只改与根因相关的代码，顺手重构/顺带优化一律推后
- 先写**失败场景的测试**（复现 bug 的用例），再改代码
- 兜底逻辑不允许静默：任何 `catch {}` 必须 `console.error`/日志/可见降级
- 涉及外部副作用（真实生图调用、真实服务、DB 写）的改动，在测试里用 noop/fixture 隔离

### ④ 自验证（E2E 优先，未过循环）

验证层级从强到弱，**至少做到第 2 级才能进入第 5 步**：

1. **E2E 探针**：临时账号走完整真实链路（本项目：注册→问答→孵化→形象→对话历史→切页回显），用完 `cleanup_probe.py` 清理
2. **针对性测试**：`python -m pytest tests/<相关模块> -q`（后端）+ `npx vue-tsc -b`（前端）
3. **服务生效确认**：重启过的服务必须确认新代码真在跑（接口 404→401 变化、探测服务端返回的模块内容与本地一致）

验证没过 → **回退（`git checkout` / 恢复 checkpoint）或继续修**，循环回到 ③；禁止带着未过的验证进第 5 步。
验证环境优先隔离：测试用 SQLite 内存库，不碰真实数据库；真实服务上的验证用探针账号，用完即清。

### ⑤ 验证通过才汇报

- 汇报内容必须包含**验证证据**：测试输出摘要、E2E 探针结果、日志确认记录
- 需要用户配合的操作（重启、刷新、配置）在要求用户做之前，自己能验证的都已验证完；给出后可闭环确认的，主动闭环（"你刷新后我看日志确认"）
- 没验证完就明说"还在验证中"，禁止"应该好了""你试试"

## 回退手册

| 场景 | 命令 |
|------|------|
| 回退本次全部改动 | `git checkout -- .`（未提交前）/ `git reset --hard HEAD`（已提交） |
| 回退单个文件 | `git checkout -- <path>` |
| 回到上一个 checkpoint | `git log --oneline -5` 找 checkpoint → `git reset --hard <sha>` |
| 改崩了但想保留现场 | 先 `scripts/checkpoint.ps1`（提交现场）再回退，现场永远可找回 |

## 与本次事故的关系（为什么有这份协议）

2026-08-15「对话历史切页丢失」排了三轮，根因是两个工作模式缺陷：

1. **没有闭环**：改完代码就让用户"刷新试试"，自己没验证；用户成了人肉探针
2. **没有证据**：反复验证正常的层（后端/测试），跳过可探测的服务层（模块半新半旧），用缓存假设填空

本协议就是把这两条缺陷变成强制步骤。每次跳过 ④ 直接到 ⑤，都会重演那次事故。
